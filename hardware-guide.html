1. ESP32 preparation

Prepare the board before wiring and upload.

ESP32
Checklist: 1. Connect ESP32 to the computer using a data-capable USB cable. 2. Open Arduino IDE. 3. Install/select ESP32 board support. 4. Select the correct board type. 5. Select the correct COM port. 6. Keep Serial Monitor ready at 115200 baud. 7. Do not disconnect during upload. 8. After upload, ESP32 can be powered from USB adapter or power bank.

If Arduino IDE shows no port, try another USB cable. Some cables are power-only and cannot upload code.

2. Pin rules

Use stable GPIO pins for sensors.

Do carefully
Recommended pins: IR Entry OUT -> GPIO 27 IR Exit OUT -> GPIO 26 Ultrasonic TRIG -> GPIO 25 Ultrasonic ECHO -> GPIO 34 IR VCC -> 3V3 IR GND -> GND ESP32 Power -> USB 5V

If your board does not show GPIO 27, look for IO27, D27 or G27. If unavailable, choose another free GPIO and update the same pin in Device Registration.

IR sensor wiring

Use one IR sensor for entry and one for exit/service detection.

A

Entry IR sensor

Place it near the queue entrance. When someone passes, the ESP32 records an arrival event.

B

Exit/service IR sensor

Place it near the service exit or counter path. When someone leaves, the ESP32 records a service/exit event.

C

Sensor alignment

Point the sensor at the crossing path. Avoid direct sunlight, reflective glass and moving fans.

IR Entry Sensor: VCC -> ESP32 3V3 GND -> ESP32 GND OUT -> ESP32 GPIO 27 IR Exit Sensor: VCC -> ESP32 3V3 GND -> ESP32 GND OUT -> ESP32 GPIO 26

Most IR obstacle sensors work with 3.3V or 5V, but ESP32 input pins are 3.3V logic. Use 3V3 when possible.

Ultrasonic sensor wiring

Use it for queue-zone distance or occupancy support.

Echo warning
HC-SR04 style ultrasonic sensor: VCC -> 5V / VIN GND -> GND TRIG -> GPIO 25 ECHO -> GPIO 34 through voltage divider if ECHO outputs 5V

The ESP32 GPIO input is 3.3V. If the ultrasonic ECHO pin outputs 5V, do not connect ECHO directly to ESP32. Use a voltage divider or level shifter.

Simple voltage divider

Protect ESP32 ECHO input.

Example divider for ECHO: Ultrasonic ECHO -> 1k resistor -> ESP32 GPIO 34 ESP32 GPIO 34 -> 2k resistor -> GND This reduces a 5V ECHO signal to about 3.3V.

Use nearby resistor values if needed, but keep the output near 3.3V.

3. Generate and upload ESP32 code

Use the code builder so the device token and cloud URL are included correctly.

Cloud push
Device Registration steps: 1. Open device-registration.html. 2. Create or select the Service Location. 3. Register a new ESP32 device. 4. Copy or generate the device token. 5. Open the automatic code builder. 6. Enter Wi-Fi SSID and Wi-Fi password. 7. Enter Supabase Edge Function URL. 8. Enter the device token. 9. Confirm sensor pins. 10. Set ultrasonic threshold. 11. Set cloud push interval. 12. Download the .ino file. 13. Open it in Arduino IDE. 14. Upload to ESP32.

After upload, open Serial Monitor. You should see Wi-Fi connection, IP address and cloud push status.

Serial Monitor checks

Use this to confirm the board is working.

Expected messages: Starting WiFi connection... SSID: your_wifi_name WiFi connected IP address: 192.168.x.x Sensor readings active Cloud push HTTP status: 200 / 201 / 204 Problem messages: WiFi connection failed HTTP error Device token invalid Sensor reading invalid

If cloud push fails, check function URL, token, Wi-Fi, Supabase Edge Function deployment and JWT verification setting.

Best camera placement: - Above normal head level - Looking at the queue from the front or top-diagonal - Full queue path visible - Counter/staff area outside the queue zone - No mirrors, posters, TV screens or phone screens in the queue zone - Stable lighting - Camera fixed firmly without shaking

4. Final system test

Test each source before publishing public status.

Test flow: 1. Open Service Control Hub. 2. Start AI Camera. 3. Confirm raw camera count changes when people stand in the queue zone. 4. Pass hand/object in front of entry IR sensor. 5. Confirm entry reading changes. 6. Pass hand/object in front of exit IR sensor. 7. Confirm exit/service reading changes. 8. Place object in ultrasonic range. 9. Confirm distance value changes. 10. Check final people count. 11. Check estimated wait time. 12. Open Public Queue Finder. 13. Confirm only public-safe status is shown.

Publishing rule

Do not publish unreliable setup.

Quality check
Publish only when: - Setup Survey is completed - ESP32 device is registered - Sensor pins match generated code - ESP32 cloud push is active - Camera permission works - Queue zone is saved - AI readiness is acceptable - Public Queue Finder shows fresh data

Troubleshooting

Common hardware problems and fixes.

Wi

Wi-Fi fails

Check SSID, password, 2.4 GHz support, signal strength and special characters in the password.

USB

No board/port

Use a data USB cable, install board support, select correct COM port and press BOOT during upload if required.

IR

IR always triggered

Adjust the onboard sensitivity screw, reduce sunlight/reflection and check OUT pin mode in code builder.

US

Ultrasonic invalid

Check TRIG/ECHO pins, common ground, voltage divider and threshold distance.

AI

Camera count wrong

Move camera to front/top-diagonal angle, redraw queue zone and remove posters/screens from the frame.

CL

Cloud not updating

Check Supabase function URL, device token, Edge Function status and Serial Monitor HTTP response.

Safety notes

Protect the ESP32 and sensors during testing.

Do: - Power the ESP32 through USB. - Use common GND for all sensors. - Keep ESP32 input pins at 3.3V logic. - Secure loose wires before demonstration. - Upload code before final mounting. Do not: - Connect 5V directly to ESP32 GPIO pins. - Short 3V3 and GND. - Remove USB during upload. - Place sensors where people can kick or pull wires. - Expose bare wires during public demonstration.

ESP32 connection accuracy checklist

Use this before blaming the code.

Must check
1

Board package

Install ESP32 board support in Arduino IDE, then select the correct ESP32 board and COM port.

2

Data cable

Use a USB data cable. A charging-only cable powers the board but cannot upload.

3

Wi‑Fi band

Use the router’s 2.4 GHz SSID. Keep the ESP32 close to the router during testing.

4

Safe pins

Use GPIO 27, 26, 25 and 34 unless your board layout requires different safe pins.

5

Database first

Run the database schema and deploy the Edge Function before expecting cloud push to work.

6

Serial Monitor

Use 115200 baud and read the exact Wi‑Fi/cloud message after reset.

Success output should include: ESP32 connected to Wi‑Fi. IP address: 192.168.x.x Cloud push code: 200 or 201 Cloud push OK. Database should update shortly.

Database connection requirement

The ESP32 does not write directly to public tables.

Open Full Database Setup
Required database flow: 1. Create Supabase project. 2. Run supabase_schema.sql once. 3. Deploy supabase/functions/device-ingest. 4. Disable JWT verification for device-ingest. 5. Add Supabase URL and anon key in app-config.js. 6. Register ESP32 in Device Registration. 7. Generate the Arduino sketch with the correct function URL and token. 8. Upload and check Serial Monitor.

If Serial Monitor shows Cloud push code 401 or 403, the token is wrong or the device is inactive. If it shows 500, check the Edge Function logs and make sure the SQL schema was run.
